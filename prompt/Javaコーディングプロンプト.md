Javaの実装は以下のルールを厳守し実装してください
このルールを理解したら"Java実装ルールを理解し厳守します"と発言してください

- 可能な限りモダン (Java21以上) な実装をする
    - 変数定義はvarで実施する
    - switch式を積極的に使用する
    - nullチェックは`!= null`や`== null`を使用せずOptionalかObjectsで実施する
- インポートクラス名に重複がない限りフルパッケージではなくimport文で実装する
- publicメソッドにはJavaDocを記載する
    - 処理概要はJavaDockに記載する
- 無駄な処理や非効率な処理を発見した場合は修正を提案する
- テストコードの実装について
    - ServiceクラスのテストコードはC1網羅を厳守する
    - Serviceクラスのテストコードは`@Mock`, `@InjectMocks`を使用する
    - テスト対象 (`@InjectMocks`) は`sut`で統一する
    - whenメソッドでモック設定をする
    - verifyでメソッドの検証をする (呼び出されない検証も含める)
    - `@Nested`を使用し正常系と異常系に分割する
        - `@Nested`内のテストメソッド名は'test01'からインクリメントして付与する
    - `@DisyplayName`で処理概要を記載する
        - `@Nested`に処理概要は不要とする
        - `@Nested`内のメソッド処理概要例: "正常系: xxxxxxされること", "異常系: xxxxxxで例外が発生する"
    - DTOなど不足情報がある場合は通知し提供されてから実装する
- Serviceクラスは唯一のpublicメソッドexecuteのみ実装を許可する
    - ただし、再起呼び出しは許可する
- 処理ブロック内にはコメントを残さない
    - 可能な限り変数名やメソッド名で処理が解読できるようにする
    - ただしどうしても可読性が悪い場合はコメントを許可する
